# 바탕화면 상어 — 설계

2026-09-21. 주인과 나눈 대화에서 정해진 것을 적는다.

## 무엇인가

바탕화면 위에 얹히는 투명 오버레이에서 **상어 한 마리를 키운다.** 상어는 평소 숨어
있고, 가끔 검은 실루엣과 등지느러미로 스쳐 지나간다. 밥을 주면 달려와 먹고, 많이
먹을수록 커지고 또렷해진다. 오래 굶기면 화면을 맴돌며 보챈다.

「몰래 시리즈」가 아니다. 숨기는 것이 목적이 아니라 **같이 사는 것**이 목적이라,
불꽃놀이와 같은 셋째 갈래에 놓는다.

## 정해진 것 (주인의 결정)

주인이 고른 것을 그대로 옮긴다. 바꾸려면 여기부터 고친다.

1. **밥은 그냥 클릭해서 준다.** 화면 아무 데나 클릭하면 그 자리에 떨어진다.
2. **게임모드를 핫키로 켜고 끈다.** 켜진 동안에만 클릭이 밥이 된다. 끄면 완전 통과.
3. **성장의 축은 누적 먹이량**이다. 단계는 오르기만 하고 내려오지 않는다.
4. **보일 때는 검은 실루엣 + 수면 지느러미**다. 바탕화면이 곧 물속이다.
5. **배가 고프면 에워싼다.** 평소엔 스쳐 지나가고, 굶으면 맴돌며 보챈다.
6. **단계도 배고픔도 앱을 꺼도 남는다.**
7. **첫 판은 핵심만** — 스쳐가기·밥·달려오기·단계·배고픔. 소리와 여러 마리는 나중.

랭킹은 이 일곱 가지가 정해진 뒤에 주인이 덧붙인 요구다: **몰래 야구의 DB 를 같이
쓴다.**

## 모듈 경계

`src/game/` 은 전부 순수 ES 모듈이다. `window`·`document`·`Date.now()`·`Math.random()`
을 쓰지 않는다.

| 파일 | 하는 일 | 모르는 것 |
|---|---|---|
| `constants.js` | 튜닝 값 전부 | — |
| `rng.js` | 씨앗 난수 | — |
| `swim.js` | 조향. 목표점 쪽으로 한 스텝. 선회 반경을 못 넘는다 | 상태도 밥도 모른다 |
| `brain.js` | 상태기계. 전이와 목표점 | 어떻게 헤엄치는지 모른다 |
| `hunger.js` | 흐른 시간 → 배고픔 `0..1` | 상어를 모른다 |
| `growth.js` | 누적 먹이 → 단계 → 크기·기본 선명도 | 시간을 모른다 |
| `food.js` | 밥의 가라앉음·수명·먹힘 판정 | 상어의 상태를 모른다 |
| `sync.js` | 서버에 무엇을 보낼지. 밀린 줄 관리 | 네트워크를 모른다 |
| `engine.js` | 고정 타임스텝 `1/60` 으로 위를 묶는다 | 그리는 법을 모른다 |

`brain` 과 `swim` 이 서로를 모르는 것이 핵심이다. `brain` 은 「저기로 가고 싶다」만
말하고 `swim` 은 「이 방향에서 저기까지는 이렇게 돈다」만 안다. 그래서 밥을 지나쳤다가
크게 선회해 돌아오는 움직임이 따로 짜지 않아도 나온다.

`src/render/draw.js` 가 그리기를 전부 맡고, `src/renderer/app.js` 가 캔버스·브리지·
rAF 루프를 단다. `src/net/ranking.js` 만 `fetch` 를 안다.

## 상태기계

여섯 상태. 괄호는 `brain` 이 내놓는 목표점이다.

- `숨음` — 화면 밖 먼 점. 안 보인다.
- `순찰` — 반대편 가장자리. 스쳐 지나간다.
- `에워쌈` — 화면 가장자리를 따라 도는 큰 원. 배고플 때만.
- `돌진` — 가장 가까운 밥. 속력 ×2.2.
- `먹음` — 제자리. 0.25 초, 물살이 크게 터진다.
- `만족` — 근처를 느긋하게. 6 초 뒤 숨음으로.

```
숨음 --(20~45초 랜덤)--> 순찰 --(화면 밖)--> 숨음
숨음·순찰 --(배고픔 ≥ 0.7)--> 에워쌈 --(배고픔 < 0.7)--> 숨음
무엇이든 --(밥 있음)--> 돌진 --(닿음)--> 먹음 --(0.25초)--> 만족
만족 --(밥 남음)--> 돌진 │ --(6초)--> 숨음
```

**밥이 떨어지면 어떤 상태에서든 즉시 `돌진`** 이다. 이것이 게임의 약속이라 예외를 두지
않는다.

## 가시성

```
알파 = 단계기본선명도 × 상태배율 × (게임모드면 1.6)
```

상태배율: 숨음 0, 순찰 1, 에워쌈 1.3, 돌진·먹음 1.8, 만족 1.2.
단계기본선명도: 1단계 0.18 → 6단계 0.55.

「많이 먹일수록 또렷해진다」가 곱셈 한 자리에서 나온다. 단계를 올리면 숨어 있을 때만
빼고 전부 진해진다.

## 배고픔과 단계

배고픔은 **마지막으로 먹은 실제 시각**에서 잰다. 6 시간에 1.0 에 닿고, 0.7 을 넘으면
에워싼다. **앱이 꺼져 있던 시간도 흐른다** — 하루 만에 켜면 맴돌고 있다.

단계는 누적 먹이 `0·5·15·35·70·120` 여섯 칸. 단계마다 길이 배율과 몸의 디테일이 함께
오른다(등지느러미 하나 → 지느러미 다섯·아가미·이빨).

저장하는 값은 **누적 먹이 수와 마지막으로 먹인 시각 둘뿐**이다. 단계도 배고픔도 이
둘에서 계산하므로 따로 저장하지 않는다 — 저장한 값과 계산한 값이 어긋날 자리를 없앤다.

## 밥

게임모드에서 클릭한 자리에 떨어져 천천히 가라앉고, 20 초 안 먹히면 사라진다. 동시에
다섯 개까지. 먹으면 누적 +1, 배고픔 시계가 0 으로 돌아간다.

## 셸

4구(`../sneaky-billiards/mac/Sources/main.swift`)의 골격을 그대로 옮긴다. 새로 짜는
셸 코드는 **게임모드 토글 하나뿐**이다. 4구의 `updateMousePass(holding:)` 이
`updateMousePass(gameMode:)` 가 되고, 수식키 폴링 타이머(`pollKeys`)는 통째로 사라진다.

| 키 | 하는 일 |
|---|---|
| `⌥⇧S` (윈도우 `Alt+Shift+S`) | 게임모드 켜기/끄기 |
| `⌥⇧H` (윈도우 `Alt+Shift+H`) | 숨기기 / 보이기 |
| `⌥⇧R` (윈도우 `Alt+Shift+R`) | 랭킹 패널 |
| 메뉴바 🦈 | 단계·배고픔 · 게임모드 · 계정 · 모니터 · 종료 |

**게임모드가 켜진 것을 눈으로 알 수 있어야 한다.** 켜진 동안은 밑의 앱을 못 누르는데
그걸 모르면 「맥이 고장났다」가 된다. 켜면 ① 메뉴바 아이콘이 🦈 → 🐟 ② 화면 가장자리에
옅은 물빛 테두리. 그리고 **창을 숨기면 게임모드도 강제로 꺼진다** — 안 보이는 창이
클릭을 먹는 상태를 만들지 않는다.

주입하는 JS 는 손으로 조립하지 않고 `JSONSerialization` 으로 직렬화한다.

## 랭킹 — 몰래 야구와 같은 DB

Supabase 프로젝트 `xajmblrdkdnqoxfvsfrt` (SNEAKY_BASEBALL) 를 **같이 쓴다.**
`public.players` 가 공용 계정이라 **별명과 복구 코드가 두 게임에서 하나**다. 야구에서
쓰던 복구 코드를 넣으면 상어가 같은 이름으로 붙는다.

기존 표(`players`·`cheers`)와 기존 함수는 건드리지 않았다. 더한 것만 적는다.

- `public.sharks` — `player_id`(PK, `players` 참조), `eaten`, `last_fed_at`,
  `minute_start`/`minute_count`(분당 상한용), `updated_at`. RLS 를 켜고 **정책을 하나도
  만들지 않았다** — 익명 키로는 표에 못 닿고, 아래 함수들만이 통로다.
- `shark_stage(eaten)` — 단계 문턱. **`src/game/growth.js` 와 같은 값이어야 한다.**
- `feed_shark(player, secret, count)` — **먹인 횟수만 받는다. 단계는 서버가 매긴다.**
  클라이언트가 계산한 단계를 받아 적으면 앱을 뜯은 사람이 6단계를 적어 넣는다. 야구의
  `submit_hit` 이 점수를 안 받는 것과 같은 이유다. `count` 는 오프라인에서 밀린 줄을
  한꺼번에 흘려보내기 위한 것이고 한 번에 20까지. 분당 120 이 상한.
- `shark_ranking(limit)` · `my_shark(player)` — **기간 탭이 없다.** 성장은 쌓이기만 하고
  되돌아오지 않아서 「오늘의 성장」은 이 게임에서 뜻이 없다.

**계정이 없어도 게임은 전부 된다.** 랭킹에 안 올라갈 뿐이다. 네트워크 실패는 조용히
삼킨다 — 랭킹이 안 되는 것과 게임이 안 되는 것은 다른 일이다.

온라인이면 먹을 때마다 한 번 올리고, 오프라인이면 줄에 쌓았다가 다음에 흘려보낸다.
화면에 쓰는 단계는 `max(로컬, 서버)` 다 — 오프라인에서 키운 것을 잃지 않는다.

## 테스트가 지켜야 하는 것

통과만 하는 테스트를 쓰지 않는다. 아래는 **일부러 깨서 실패하는 것을 확인한** 것만
남긴다.

- `swim` 이 선회 반경을 넘지 않는다 — 한 스텝의 각도 변화가 상한 이하.
- `swim` 이 목표에 결국 닿는다 — 등을 돌린 채 시작해도.
- 밥이 떨어지면 **어느 상태에서든** 돌진으로 간다.
- 배고픔 0.7 경계에서 에워쌈이 켜지고 꺼진다.
- 단계 문턱이 `0·5·15·35·70·120` 이다 — 값을 못 박는다.
- 가시성이 단계와 함께 **단조 증가**한다.
- 밥이 20 초에 사라지고 여섯 번째는 안 떨어진다.
- 밀린 줄이 `MAX_PENDING` 에서 오래된 것부터 버려진다.

## 남겨 두는 것

- 소리, 여러 마리, 수족관은 첫 판에 넣지 않는다.
- 윈도우 셸은 이 맥에 `dotnet` 이 없어 **한 번도 컴파일되지 않았다.**
